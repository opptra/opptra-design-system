01 / Brand language

Confident. Grounded. In motion.

The website's sense of ownership becomes a clear voice for both brand storytelling and operational work.

01
01

Take ownership

02

Make it concrete

Lead with the outcome, then support it with evidence. Explain automation in terms of the work it handles.

03

Keep people moving

Use short, useful language. Keep calm when something fails and give a specific way to recover.

Orange needs a deliberate foreground.

Use navy text on orange actions (5.24:1). White on brand orange is 3.16:1 and fails the 4.5:1 ordinary-text threshold. Small orange links use proposed #B53F00 on white (5.71:1). Ratios are color calculations, not a full accessibility assessment.

C24 / Accordion
When should I use orange?

For a clear point of emphasis: a prominent CTA, an active marker or one chart highlight. Use navy text on orange actions.

Can I change the typefaces?

Use Spectral for headings and Raleway for body and UI. Georgia and Segoe UI are the network fallback.

Is this a production library?

This is a design reference and handoff. Framework implementation, real-user validation and production QA follow adoption.

09 / Adoption

Start small. Keep it coherent.

Use this reference to make the next design decision. Build and validate a production library in the context of a real product.

09
  1. 01
    Choose the task, then the component.Reuse an existing pattern before adding one. Keep expressive marketing layouts and practical product density on the same tokens.
  2. 02
    Use semantic names.Reference --color-action-primary rather than copying a hex value. Preserve the original brand primitives.
  3. 03
    Describe the states before building.Include permission, missing data, source freshness and recovery. Ask who owns a decision before an interface implies it.
  4. 04
    Version the change and show the migration.Proposed ownership: design steward + engineering maintainer, appointed by Opptra. Review additions against a real use case and record breaking changes.

Before adoptionConfirm brand approval, owner, product priorities, font distribution, supported browsers and technology stack.

Before production releaseImplement and test the component API, keyboard behavior, screen readers, responsive layouts, real data, permissions and content.
